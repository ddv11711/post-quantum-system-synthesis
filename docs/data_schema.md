# Схема данных и публичный API

Снимки, профили, отчёты и действия представлены JSON-совместимыми словарями Python. [schemas/model.schema.json](../schemas/model.schema.json) — документирующая JSON Schema Draft 2020-12 для снимка, фактов, требований, переходов, действий и исходного графа. Анализатор **не вызывает JSON Schema автоматически**. Выполняемая проверка формы, типов, ссылок и согласованности — `analyzer.model.validate_model`; именно её диагностика определяет MODEL_ERROR. JSON Schema не заменяет проверку существования узлов, совпадения типов аргументов, конфликтов фактов, политик или безопасности ремонта.

## Снимок модели

| Поле | Значение |
|---|---|
| `state` | Строковый идентификатор версии состояния, независимо от ПК |
| `parent_state` | Идентификатор исходного состояния после перехода |
| `profile` | Имя выбранного строгого, локального демонстрационного либо отдельного сценарного профиля |
| `nodes` | Объект `node_key → node`; ключ сохраняется для подсветки и экспорта матриц |
| `source_graph` / `raw_graph` | Отдельный нетипизированный исходный граф, включая происхождение и проблемы импорта |
| `facts` | Массив типизированных ground-фактов |
| `completeness` | Явные полные/неполные области отношений |
| `dependencies` | Полные конечные AND/OR-уравнения работоспособности по ключам компонентов |
| `dependency_provenance` | Источники уравнений по ключам компонентов, сохраняемые в дереве вывода |
| `transitions` | Типизированные семантические переходы в контексте субъекта/операции/сценария |
| `requirements` | Неизменяемые обязательства и запреты, выраженные исполняемыми checker-спецификациями |
| `policy.allowed` | Эталонные разрешения; они не меняют фактические ACL и не создают переходы |
| `mutable` | Явный список изменяемых пар `(predicate,args)` |
| `action_catalog` | Конечные разрешённые действия с точными эффектами |
| `assumptions` | Видимые допущения; демонстрационные записи помечены `demo_assumption` |
| `actions`, `diff` | Применённый атомарный набор и изменения фактов с предыдущими значениями/свидетельствами |
| `import_issues`, `comparison`, `profile_source` | Неполнота источников, выбранные условия сравнения и источник семантического слоя |

`empty_model(state='initial', profile='strict')` создаёт пустые коллекции. Формат допускает дополнительные описательные поля, но это не расширяет конечный реестр предикатов или поддержанные checker. Названия ПК не используются как временная последовательность состояний.

Узел содержит исходные `key`, `id`, `pc`, `name`, `provenance` и семантический массив `types`. `id` может повторяться на разных ПК; словарь индексируется только `key`. Общие узлы имеют `pc=null`. При импорте тип — `unknown`; профиль назначает типы явно. Допустимы `component`, `subject`, `data`, `function`, `event`, `key`, `role`, `channel`, `change`, `unknown`. Наличие типа `unknown` означает, что конкретный тип ещё не установлен, а не выдаёт права или значение проверяемого свойства.

## Факт и происхождение

```json
{
  "predicate": "acl",
  "args": ["2:99", "g:104", "read"],
  "value": "UNKNOWN",
  "provenance": [{
    "file": "semantic_profile.json",
    "json_key": "facts[0]",
    "state": "example",
    "raw_value": null,
    "transformation": "ACL не предоставлена источником",
    "kind": "declared"
  }]
}
```

Ключ факта — имя предиката и упорядоченные аргументы. Для `independent` порядок пары семантически симметричен. Значения булевых предикатов — строки `TRUE`, `FALSE`, `UNKNOWN`; на входе фактов также принимаются JSON `true`/`false`. Рекомендуется использовать канонические строки во всех моделях, требованиях и эффектах. `None`/`null` не является допустимым значением ground-факта; неизвестность записывается явно как `UNKNOWN` или возникает из отсутствия записи.

Скалярные предикаты допускают строку, число или булево значение, но `FactBase.get` нормализует чтение в строку. Поэтому для сравнения конфигурации следует согласованно использовать строковые параметры и `expected`, например `"256"`. Арифметические сравнения и сроки не являются отдельным языком выражений. Квантовый checker сам преобразует размер параметра в целое число в своём ограниченном сценарии.

Provenance — массив источников; совпавшие импортированные декларации не теряют второе свидетельство. Поля `file`, `sheet`, `cell`, `json_key`/`location` описывают место; `raw_value`/`original` — исходное значение; `transformation`/`method` — преобразование; `state` — привязку; `kind` — `imported`, `declared`, `demo_assumption` либо `derived`. Дополнительные поля могут хранить исходное состояние, допущение, ID действия. Справочная схема разрешает пустую provenance для программных фикстур; это не делает такую запись внешне подтверждённым фактом.

## Конечный реестр предикатов

`node` означает любой объявленный ключ. `label` — строка из конечного явно использованного в модели словаря меток. `operation` — `read`, `write`, `execute`, `administer`. `transition` — ID объявленного семантического перехода. Данные типы проверяются отдельно от внешнего представления строкой.

| Предикат | Аргументы | Смысл |
|---|---|---|
| `present` | node | Физическое/инвентарное присутствие экземпляра |
| `enabled` | node | Административное включение функции |
| `healthy` | node | Подтверждённая собственная исправность |
| `transport_enabled` | node | Включение транспортной функции отдельно от защиты |
| `failure_mode` | node | Скалярный режим, в том числе `normal`, `fail_open`, `fail_closed` |
| `acl` | subject, node, operation | Фактическая ACL; не эталонное разрешение |
| `physical` | node, node | Явно типизированное физическое соединение |
| `channel` | node, node | Назначенный канал передачи |
| `stores` | node, data | Размещение/хранение данных |
| `executes` | node, node | Назначенная связь исполнения |
| `owns` | subject, data | Владелец данных; не автоматическая ACL |
| `authenticates` | subject, node | Явное отношение аутентификации |
| `cover` | node, label, node | Механизм покрывает объект по указанной защитной функции |
| `logger` | event, node | Регистратор покрывает событие |
| `event_possible` | event | Данное событие возможно в выбранном сценарии |
| `backup` | data, node | Кандидат резервной копии данных |
| `readable` | node | Копия доступна для чтения/использования |
| `key_required` | node, key | Для копии необходим ключ |
| `key_accessible` | key | Требуемый ключ доступен для восстановления |
| `independent` | node, node | Подтверждённая независимость пары механизмов/реплик |
| `integrity` | node | Наблюдённое состояние целостности |
| `trusted_boot` | node | Наблюдённое состояние требуемой доверенной загрузки |
| `parameter` | node, label | Скалярный фактический параметр |
| `has_role` | subject, role | Действующее назначение роли |
| `changed` | change | Исторически подтверждённое изменение |
| `approved` | change | Подтверждённое согласование изменения |
| `crypto_protected` | channel | Требуемая защита заданного участка |
| `crypto_algorithm` | channel | Скалярное конкретное название алгоритма |
| `crypto_function` | channel | Скалярное назначение криптографической функции |
| `crypto_bits` | channel | Скалярный размер параметра в заявленном сценарии |
| `material_available` | subject, channel | Нужный для сценария материал доступен нарушителю |
| `observes` | subject, channel | Нарушитель наблюдает конкретный поток |
| `quantum_capable` | subject, label | Явно принятая возможность в данном временном горизонте |
| `horizon_valid` | channel, label | Условие применимости данного горизонта к потоку |
| `evidence` | node, label | Внешнее свидетельство по названному документному условию |
| `transition_enabled` | transition | Управляемый факт для включения заранее объявленного перехода |

`available`, `transport`, `can_perform`, `reachable`, `quantum_exposed` — производные понятия, а не свободно редактируемые исходные предикаты. Конкретный квантовый результат называется `passive_quantum_exposure` и не сохраняется как ACL. Использование неподдержанного ground-предиката диагностируется, а не интерпретируется как произвольное расширение логики.

## Полнота и зависимости

```json
{
  "predicate": "cover",
  "args_prefix": ["1:64", "filtering"],
  "complete": true,
  "provenance": [{"kind": "demo_assumption", "file": "demo_profile.json"}]
}
```

Это утверждает полноту только альтернатив `cover(1:64,filtering,*)`. Для переходов префикс имеет порядок `[subject, operation, scenario, kind]`, например `["2:99","read","default","access"]`. Для зависимостей используется специальный предикат `dependencies` с префиксом `[node]`. Пустой префикс означает всё отношение. Несовместимые записи полноты одного и того же префикса дают MODEL_ERROR. Отрицательные исключения из более широкого полного префикса не предусмотрены.

```json
{
  "dependencies": {
    "service": {"all": ["cpu"], "any": ["primary", "backup"]},
    "cpu": {"all": []}
  }
}
```

Здесь сервису нужен CPU и хотя бы одна из двух альтернатив. Каждое явное уравнение считается полным перечислением его операндов. Отсутствующее уравнение без отдельной полноты не считается пустым: работоспособность остаётся UNKNOWN, если нет достаточного отрицательного основания. Циклы не объявляются работоспособными по собственным ссылкам. Вложенные AST, произвольные отрицания и последовательность запуска отсутствуют в формате.

## Семантический переход

```json
{
  "id": "nas-read-interface",
  "source": "user",
  "target": "nas",
  "subject": "user",
  "operation": "read",
  "scenario": "default",
  "kind": "access",
  "value": "TRUE",
  "conditions": [
    {"predicate": "acl", "args": ["user", "nas", "read"], "expected": "TRUE"},
    {"predicate": "available", "args": ["nas"], "expected": "TRUE"}
  ],
  "provenance": [{"kind": "demo_assumption", "file": "profile.json"}]
}
```

Переход требует присутствия концов и необязательного `via` автоматически. Остальные условия задаются явно. `kind` — `access` или `flow`, по умолчанию `access`; `scenario` по умолчанию `default`. Условия сравнивают факт либо `available`/`transport` с `expected` (или с `value`, по умолчанию TRUE). Неизвестное значение сравнения даёт UNKNOWN. `transition_enabled` действует только если добавлен в `conditions`; наличие факта не включает произвольное ребро автоматически.

Для пути сохраняются субъект, операция, сценарий и вид. `switch_subject` или непустые `grant_roles` не поддерживаются. Исходные HTML/XLSX-рёбра в этот список автоматически не попадают. Удаление объекта гасит связанные переходы, но не соединяет его соседей.

## Требования и эталонные разрешения

Общие поля требования: уникальный `id`, `checker`, `object`/`subject`, `name`, `rule_id`, список `catalog_rule_ids`, `applicable`, `catalog_scope`, `provenance`, `repair_options`. Применимость рекомендуется всегда задавать явно. Для включённого в исполняемый локальный профиль требования отсутствие `applicable` означает TRUE; это принятие требования составителем профиля. Для исходного нормативного каталога применимость хранится отдельно и по умолчанию UNKNOWN.

| Checker | Специальные поля |
|---|---|
| `forbidden_operation`, `required_operation` | `subject`, `object`, `operation`; дополнительно `scenario`, `kind`, `source` |
| `required_function` | `object` |
| `protection` | `object`, `control` (по умолчанию `protection`); для обхода `bypass_subject`, `operation`, `scenario` |
| `authentication` | То же; `control` по умолчанию `authentication` |
| `logging` | `object` — событие |
| `redundancy` | `object`, массив `replicas`, флаг `replicas_complete` |
| `recovery` | `object` — данные |
| `configuration` | `object`, `predicate` (по умолчанию `integrity`), `args` (по умолчанию `[object]`), `expected` (по умолчанию TRUE) |
| `incompatible_roles` | `subject`, `roles` из минимум двух ролей; нарушение означает наличие всех ролей объявленной комбинации |
| `authorized_change` | `object` — изменение |
| `crypto` | `object` — канал; необязательные ожидаемые `algorithm`, `function`, `bits`, список обязательных `endpoints` |
| `quantum` | `object` — канал, `subject` — нарушитель, явный `horizon` |
| `evidence` | `object`, `document` (по умолчанию `required`) |

Для защиты/аутентификации обход проверяется только при явно заданном `bypass_subject`; его сценарий по умолчанию `bypass`. Не следует полагать, что отсутствие этого поля означает аудит всех неизвестных обходов. Для криптографической непрерывности нужно перечислить все требуемые участки; checker одного канала не инвентаризирует весь поток.

Запись `policy.allowed` содержит `subject`, `object`, `operation`, необязательные `scenario`, `kind`, `applicable`, `provenance`. Разрешение означает, что операция допустима по эталону; оно не обязывает её иметь место. Обязательная операция задаётся отдельным `required_operation`. Разрешение или обязанность одновременно с запретом того же контекста при TRUE-применимости — MODEL_ERROR. Фактическое разрешение хранится отдельно в `acl` и условиях переходов.

`catalog_scope=fragment` — значение по умолчанию. Для исходного пункта каталога PASS не получается из одного частичного успешного checker. Полное `catalog_scope=complete` — ответственное утверждение составителя профиля о полноте формализации исходного условия, а не автоматически назначенная характеристика. Подробнее: [покрытие каталога](catalog_coverage.md).

## Действия и переходы состояния

```json
{
  "id": "restore-approved-logger",
  "object": "logger",
  "cost": 1,
  "targets": ["mandatory-event-logging"],
  "preconditions": [{"predicate": "enabled", "args": ["logger"], "value": "FALSE"}],
  "effects": [{"predicate": "enabled", "args": ["logger"], "value": "TRUE"}],
  "requires": [],
  "excludes": [],
  "provenance": [{"kind": "demo_assumption", "file": "action_catalog.json"}]
}
```

`mutable` должен заранее содержать `{"predicate":"enabled","args":["logger"]}`. Стоимость — неотрицательное целое; по умолчанию 1. `targets` помогает привязать шаблон к находкам; генератор дополнительно сопоставляет эффекты с фактами из свидетельств и зависимостей. `requires` задаёт совместно выбранные действия, `excludes` — запрещённые совместные действия. Все предусловия проверяются **в исходном снимке**, а эффекты применяются атомарно.

Эффект не может менять неизвестный факт, вводить UNKNOWN, противоречить другому эффекту или затрагивать неразрешённый ground-ключ. Даже запись в `mutable` не делает изменяемыми `evidence`, `approved`, `changed`, `owns`, `event_possible`, `material_available`, `observes`, `quantum_capable`, `horizon_valid` или производные факты. Нельзя устранить дефицит журнала, просто объявив обязательное возможное событие невозможным. Отсутствующий ground-факт может быть известным FALSE только при явно полном отношении; его изменение допустимо лишь при заранее объявленной изменяемости и остальных выполненных ограничениях.

API переходов: `apply_actions(model, actions, new_state=None)`, `remove_component`, `disable_component`, `fail_component(mode='fail_closed')`, `set_parameter`, `set_acl`, `set_relation`. Они возвращают копию и diff; исходная модель не меняется. Удаление сохраняет ключ как отсутствующий экземпляр. Для API отказа должны быть известны и изменяемы `healthy` и `failure_mode`. Для отключения достаточно разрешённого `enabled`; транспорт остаётся отдельным условием.

| `analyze(model)` | Все результаты, summary, ошибки модели, работоспособность, итерации, измерения времени |
| `reachability(model, subject, target, operation, scenario='default', kind='access', source=None)` | Значение, свидетель, полнота, неизвестности и evidence |
| `generate_candidates(model, report=None)` | Конечные разрешённые кандидаты и основания отбора |

| `export_matrices(model)` | Индексы, структурная матрица, контекстные must/may и отдельные матрицы политики |
| `load_catalog(path)` / `coverage(catalog, analysis=None, applicability=None)` | Полный исходный реестр и отдельный результат для каждого ID |

Аргументы лимитов `find_repairs` именованные. Поддержанный ремонт — атомарный набор; API не обещает безопасность последовательного выполнения. JSON Schema описывает форму действия, но не доказывает известность его предусловий, допустимость эффектов или сохранность обязательных функций.

## Экспорт и воспроизводимость

Находка включает статус, ID checker/каталога, профиль/состояние, объект/операцию/субъекта, причины, свидетельствующие факты, источники, путь/дерево, неизвестности и варианты изменений. Список `cause_components` отличается от `object`. Поиск добавляет пространство действий, ограничения, целевую функцию, число проверенных наборов, причины отклонений, пределы, выбранные действия, статус оптимальности, новую модель и независимую повторную проверку публичным API.

Объекты матриц содержат `node_key_to_matrix_index` и обратный список; порядок ключей устойчив к перестановке строк источника. Контекстные матрицы содержат `row_keys`, `column_keys`, `values`, `must`, `may`, `scope_complete`; policy-матрицы содержат отдельное отношение. Исходная структурная матрица не является матрицей разрешений. Неполнота и неподдержанные проверки не заменяются средним баллом.

Схема допускает дополнительные поля для provenance и отчётного контекста. Семантическая совместимость определяется версией исполняемого кода и профиля; неподдержанный checker не превращается в PASS после успешной структурной проверки JSON. Точные команды полного воспроизводимого запуска и проверенные версии зависимостей приведены в README.
